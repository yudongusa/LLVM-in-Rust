# Crash triage runbook

This runbook defines the Gate 3 crash and miscompilation triage process.

## Triage SLO

- First maintainer response: within 1 business day.
- Reproducer confirmation: within 48 hours or the next triage cycle.
- Bucket assignment: before closing or merging the fix PR.
- CI crash artifacts: retained for at least 14 days.

## Labels

Use these labels to make crash state explicit:

- `bug`: confirmed defect or actionable report.
- `crash`: parser, optimizer, codegen, or harness crash.
- `miscompilation`: wrong-code or semantic mismatch.
- `timeout`: non-terminating or excessive-runtime input.
- `needs-repro`: report is missing a runnable reproducer.
- `repro-confirmed`: maintainer reproduced the failure on current `main`.

## Bucket signature

Bucket signatures group duplicate failures without requiring exact identical inputs.
Use this format:

```text
<component>:<failure-kind>:<top-error-or-panic-line>:<12-char-input-hash>
```

Examples:

```text
llvm-ir-parser:panic:thread 'main' panicked at src/parser.rs:123:abcd1234ef56
codegen-x86:crash:LLVM ERROR invalid register:112233445566
```

## Evidence package

Every actionable crash or miscompilation should have an evidence package with:

- `original.ll`
- `minimized.ll`
- `reducer.log`
- `repro.sh`
- `manifest.txt`
- `bucket-signature.txt` when generated by CI
- link to the CI run and uploaded artifact, when applicable

## Flow

1. Reproduce the failure on current `main`.
2. Assign labels: `bug` plus `crash`, `timeout`, or `miscompilation`.
3. Run the reducer when a failing `.ll` input is available:

   ```bash
   scripts/reduce_ci_failure.sh \
     --input failing.ll \
     --predicate './repro.sh {{input}}' \
     --evidence-dir ci-failures/example
   ```

4. Attach or link the evidence package in the issue.
5. Record the bucket signature in the issue.
6. Assign an owner for the fix.
7. Keep the issue open until the fix PR is reviewed, CI is green, and questions are resolved.

## CI artifact policy

GitHub Actions should upload `ci-failures/**`, `csmith_failures/**`, fuzz artifacts,
and crash bucket summaries on failing or scheduled crash-triage runs. CI artifacts are
not issue attachments; maintainers should link the run/artifact URL from the issue.
